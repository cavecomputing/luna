# Windows development

Luna supports Windows 10/11 on x64. Build Windows release artifacts on Windows; build the
macOS DMG on macOS. This keeps Electron's native packaging and future code-signing steps on
the platform where they are easiest to verify.

## Prerequisites

- Node.js 22 or newer
- Git for Windows
- npm, included with Node.js

Visual Studio or its C++ build tools are not currently required. Luna has no third-party
native Node addon; the database uses the SQLite API built into Electron's Node runtime.

## First setup

From PowerShell:

```powershell
npm.cmd install
npm.cmd run dev
```

Some Windows PowerShell configurations block Node's `npm.ps1` shim. This is a local execution
policy choice, not a Luna failure. Use `npm.cmd` as shown above, or use `npm` from Command
Prompt or Git Bash. Changing the machine execution policy is not required.

`npm install` runs `scripts/setup-hooks.mjs`. The Node script points Git at the committed
`.githooks/` directory on both operating systems. The hooks themselves remain POSIX shell
scripts because Git for Windows supplies the shell and Unix utilities used to run them; `sh`
does not need to be on PowerShell's `PATH`.

## Development and checks

```powershell
npm.cmd run dev
npm.cmd run typecheck
npm.cmd run lint
npm.cmd run test
```

Renderer edits hot-reload. Main-process and preload edits restart Electron. Luna uses the
standard Windows title bar and window controls; the inset title bar and traffic-light
positioning are applied only on macOS.

Application preferences and the conversation database live under Electron's Windows
`userData` directory, normally `%APPDATA%\Luna`. Build output does not contain that data.

## Build outputs

```powershell
npm.cmd run build
npm.cmd run package
npm.cmd run dist
```

- `build` checks and bundles the application into `out/`.
- `package` creates the unpacked application at `release/win-unpacked/Luna.exe`.
- `dist` creates `release/Luna-Setup-<version>-x64.exe` using NSIS.

The Windows target is currently x64 only. Both `out/` and `release/` are ignored by Git and
can be deleted whenever a clean rebuild is useful.

## Distribution notes

Local builds are not Authenticode-signed. Windows may therefore display a SmartScreen warning
when the installer is downloaded or moved to another computer. That is expected during local
development. Public releases should be signed with a Windows code-signing certificate and
tested on a clean Windows account before publishing.

Electron applications are comparatively large, and a clean package may trigger an antivirus
scan while `Luna.exe` is being written. A slower first package is not necessarily a hung build.

The Windows executable icon is generated by electron-builder from
`assets/LunaAppIcon/icon.png`. If Windows Explorer continues showing an older icon after it is
changed, rebuild the package first; Explorer may also retain the old icon in its cache.

## Troubleshooting

### `sh` is not recognized during `npm install`

The checkout is using the old lifecycle configuration. Confirm `package.json` runs
`node scripts/setup-hooks.mjs`, then rerun `npm.cmd install`.

### `npm.ps1 cannot be loaded because running scripts is disabled`

Run the same command with `npm.cmd`, or use Command Prompt/Git Bash.

### Re-enable the Git hooks

```powershell
npm.cmd run setup
git config --get core.hooksPath
```

The second command should print `.githooks`.
